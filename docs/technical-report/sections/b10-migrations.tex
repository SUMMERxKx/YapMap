\chapter{Migration history}
\label{app:migrations}

The database is defined by thirteen migrations in \code{supabase/migrations}. Each file is named
\code{<version>_<name>.sql}, and the migrations apply in version order. This report refers to each by its
name (\cref{tab:migrations}), listed in the order they apply, with its version below it. Later migrations
replace earlier definitions; the descriptions in this report always refer to the latest one.

Every version is the one the hosted project recorded when the migration was applied, so the file names
and the hosted migration history list exactly the same versions. Migrations applied with the Supabase MCP
tool are recorded under the time they ran, so \code{content_moderation} and \code{break_it_hardening}
were renamed after they were applied, from \code{20261022082408} and \code{20261022083815}; their
contents did not change. The Migration files check in CI (\code{scripts/check-migrations.sh}) allows such
a rename only when the file stays byte for byte the same, and fails any edit or deletion of an existing
migration. The two migrations of 26 October 2026 are applied to the hosted project with
\code{supabase db push}, which keeps the file versions, together with switching on the Before User
Created hook in the dashboard.
