# YapMap store release readiness

**Audit date: 11 November 2026. Status: needs work before either store submission.**

The app has useful safety controls in source, including report, block, text filtering, account restrictions and deletion. The selected manual-verification launch needs a real review backend, server enforcement and approval reset on photo changes. The code pass also found an onboarding deletion gap and a restricted-profile read/photo authorization gap. Public pages, disclosures and review access remain submission gates. Store account and production backend readiness remain unverified.

This report is published for contributors to plan the remaining release work. It changes no application code, hosted settings, accounts or store submissions.

## Code review update after the launch scope decision

**Launch scope recorded on 11 November 2026:** manual selfie review now, with an automatic matching service considered later. The captain is the seller and account owner. Launch is **Canada only**. The captain is the moderator. Actual account registration type and service settings still need verification. These choices are settled for this report.

The requested next step is a contributor-facing code checklist. Documentation, store forms and account setup can be finished later, but remain submission gates. This review changes no application code.

### Suggested implementation order

1. Fix C3 and C4 first. They are small, independent safety changes and do not depend on a face matching vendor.
2. Implement C1 and C2 together, including private storage, the owner review tool, photo-version binding and backend enforcement. Make C7 part of that feature so the UI never claims a result the server has not issued.
3. Implement C5 and C6, then rehearse the owner's full moderation flow. Keep selfies separate from ordinary profile-photo permissions.
4. Resolve C8, configure the release project and Maps key, then validate signed iPhone and Android builds against the existing release checklist.
